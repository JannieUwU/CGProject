# 第三项反馈：改动说明与查看指南

更新时间：2026-11-21。

本文介绍第三项“MSAA 着色位置与深度测试分离”的实际改动、查看方法和演示例子，包括后续减少重复计算的优化。前三项、重复点击修复和局部打磨均保留。土星两项阴影过滤保留为后续优化方向。

## 1. 这次做了什么

4× MSAA 会检查像素里的四个采样位置，但同一个三角形片段通常只完整计算一次颜色，再让合格的采样点共享结果。

以前，“第一个通过深度测试的合格样本”决定在哪里计算颜色。如果前面的物体挡住了这个样本，后面的三角形就可能换一个位置取色，连仍然露在外面的部分也跟着换颜色。

现在把两个问题分开：先由三角形的几何覆盖决定“在哪里算颜色”，再由深度等检查决定“哪些点能使用这份颜色”。

| 改动 | 现在怎样处理 | 带来的好处 |
| --- | --- | --- |
| 几何选点与遮挡分离 | 用中心、完整几何覆盖平均点或固定后备决定位置 | 几何条件不变时，不因深度通过集合变化而改换取色点 |
| 中心优先 | 中心属于当前三角形且属性有效时，在中心着色 | 减少总偏向第一个角样本的位置偏向 |
| 明确平均点与后备 | 中心不可用时按固定规则继续寻找有效位置 | 薄三角形、云层等情况有明确处理与解释 |
| 保留逐样本数据 | 每个接收点仍用自己的深度、拾取 UV 和混合底色 | 共享颜色不会变成共享错误的遮挡或拾取信息 |
| 记录实际规则和原因 | 原有详情中显示 Location rule 及必要的失败原因 | 能解释菱形为什么画在这里 |
| 后续减少重复计算 | 延后无用属性准备，复用云层已算出的深度 | 已检查画面和记录不变，同时降低部分 MSAA 耗时 |

这次修改三角形 MSAA，包括本体、云层和环带。普通采样、SSAA 仍在各自的样本位置着色；独立大气射线与轨道仍按原策略处理。

## 3. 如何进入并查看

1. 打开当前程序，选择地球或土星，等待进入近景。
2. 选择 `4× MSAA`，开启 `Inspect`，点击一个像素。
3. 在右侧 `Pixel` 先看 `Pixel zoom`，再手动展开 `Details → Processing history`。
4. 用 `Record … of …` 找一条本体、云层或星环的三角形记录。若要看着色位置，先选实际着色调用大于零的记录。
5. 看采样点示意图，再展开 `Shading and depth values`，读取坐标和 `Location rule`。
6. 如果出现 `Center not used` 或 `Centroid not used`，查看前一个候选位置为什么没采用。
7. 展开具体的 `Sample … details`，核对哪些点被挡住、哪些点实际收到共享颜色，最后看 `Final resolve`。

中心着色时，菱形通常位于四个圆圈之间；平均点也可以落在圆圈之间。菱形标记实际着色位置，四个圆圈标记覆盖采样位置。没有实际调用时不画菱形；透明度为零的真实调用仍会记录。

在 `Compare` 中，可以对比当前 SSAA 与 MSAA 的调用和结果。左右同步放大同一个局部位置，详细记录仍来自实际点击的一侧；这个入口用于当前版本的采样方法对照。

## 4. 现在按什么顺序选择着色位置

| 顺序 | 位置 | 采用条件 |
| --- | --- | --- |
| 1 | 像素中心 `(0.5,0.5)` | 中心属于当前三角形、插值有效；云层还要通过朝向检查 |
| 2 | 全部几何覆盖样本的位置平均值 | 中心不可用，平均点的插值及必要的朝向检查有效 |
| 3 | 固定几何后备样本 | 前两者不可用，从全部几何覆盖样本中选择有效且离中心最近的点，等距按固定编号 |
| 都不可用 | 不着色、不写入这个片段 | 记录具体失败原因 |

“全部几何覆盖”包括三角形覆盖的所有样本，其中也包括被其他表面遮挡的样本。先平均屏幕采样位置及对应的几何权重，再进行透视校正，计算该位置的 UV、法线和颜色。

中心可能被前面的物体挡住，但仍可以作为后方三角形计算共享颜色的位置。选点负责“在哪里算”，各接收样本继续独立执行深度测试。

实际计算会等到确认存在接收样本后才执行，因此全部被挡住时仍是零次着色。一次调用得到零透明度时记录为 Transparent，该片段保留这次调用结果。

## 5. 每一项是什么意思

主要查看路径仍然是原来的详情层级：

```text
Pixel
└─ Details
   └─ Processing history
      ├─ Record … of …、覆盖/深度/着色/写入摘要及示意图
      ├─ Shading and depth values
      │  ├─ 实际坐标、共享颜色、透明度和 Location rule
      │  ├─ 必要时显示 Center not used / Centroid not used
      │  └─ Sample … details
      └─ Final resolve
```

上图的规则文字直接显示在原有面板内，沿用现有展开层级。

| 名称 | 用人话理解 |
| --- | --- |
| Pixel center | “这次在像素正中间算颜色。”坐标为 `(0.5,0.5)`。 |
| Coverage centroid | “中心用不了，于是用所有被三角形盖住的检查点的平均位置。”它以离散采样位置计算平均值。 |
| Covered sample fallback | “前两个位置不合适，按固定规则选一个有效覆盖点兜底。”候选来自全部几何覆盖样本。 |
| Location rule | “这次实际采用哪条选点规则？”它描述已经发生的调用。 |
| Center not used | “为什么没用中心？”例如不在覆盖内、插值无效或云层背向。 |
| Centroid not used | “为什么平均点也没用？”只有需要说明时才出现。 |
| Sample position | 普通采样和 SSAA 在各自样本位置着色。 |
| First eligible ray sample | 大气独立射线沿用首个合格射线样本的选点策略。 |
| 共享颜色 | 多个接收样本使用同一次计算结果，各自的深度、拾取和混合仍独立。 |
| Shading calls / Shades | 前者是所看记录中的调用；Frame cost 的 Shades 是整个视图的调用总数。 |

技术报告中的 G、D、W 分别表示“几何盖住哪些点”“哪些点通过必要检查能够接收”“最后实际写了哪些点”。这些记号用于技术说明，界面通过覆盖、深度和写入结果展示对应信息。

## 6. 用一个例子串起来

以下用一个简化的教学示例说明遮挡与选点的关系。假设四个样本都被后方三角形覆盖，其有效中心为 `(0.5,0.5)`，表面颜色随位置变化。暂不考虑透明、云层和大气。

### 第一步：没有前景遮挡

四个样本都能接收颜色。旧规则在样本 1 的 `(0.25,0.25)` 计算一次；新规则在中心计算一次。两种规则的结果可能不同，因为取色位置不同。

### 第二步：前景先挡住样本 1

后方三角形的几何覆盖没有变，但样本 1 深度被拒绝，只有 2、3、4 能接收后方颜色。

| 情况 | 旧规则的取色位置 | 新规则的取色位置 | 后方颜色实际写给谁 |
| --- | --- | --- | --- |
| 没有遮挡 | 样本 1，`(0.25,0.25)` | 中心，`(0.5,0.5)` | 1、2、3、4 |
| 样本 1 被挡住 | 样本 2，`(0.75,0.25)` | 仍是中心，`(0.5,0.5)` | 2、3、4 |
| 四个样本全部被挡住 | 不调用 | 不调用 | 都不写 |

遮挡改变后，后方三角形继续使用原来的位置计算共享颜色。样本 1 改为显示前景物体，整像素最终颜色随前景颜色和覆盖情况变化。

### 第三步：在历史里核对

查看后方三角形这条记录时，可以依次解释：几何覆盖四个点；其中样本 1 被挡住；实际在中心着色一次；颜色写入 2、3、4。展开样本 1 的详情，会看到原有前景深度和颜色没有被后方覆盖。

### 第四步：再看一个中心不可用的例子

假设另一个薄三角形只覆盖左上、右上两个样本，中心不属于它，而平均点有效。位置平均后为 `(0.5,0.25)`，菱形落在上面两个圆圈之间。

即使左上样本被遮挡，平均位置仍由两个几何覆盖样本决定；最终由右上样本接收这份共享颜色。

普通采样只有中心一个样本；4× SSAA 会在各个合格样本各算一次颜色；4× MSAA 在上述每个三角形片段/像素内共享一次。整个像素的着色次数由各三角形片段和其他效果的调用累计而成。

## 7. 展开与收起的规则有没有变化

| 操作 | 预期表现 |
| --- | --- |
| 开启检查，点击像素 | 自动进入 Pixel，Details 默认收起 |
| 展开 Details | Processing history 仍需手动打开 |
| 收起任一上级，再打开 | 它的全部后代恢复收起，同级分支不受影响 |
| 换像素、换星球或换采样方式 | 全部详情重置，处理记录回到第一条 |
| 同一选择正常刷新或测速完成 | 保留正在查看的展开状态 |
| 再次点击当前近景星球名称 | 保留镜头、像素、Inspect/Compare、详情及有效测速 |

新规则和选点原因显示在原有详情中，Details 继续采用手动展开。

## 8. 建议怎样演示

按“找菱形 → 读规则 → 看谁接收 → 对比调用”的顺序即可。

1. 在地球近景的 4× MSAA 中选一个像素，找到有着色调用的本体三角形记录。看中心菱形和 `Location rule: Pixel center`，说明圆圈负责覆盖/深度，菱形负责实际取色。
2. 移到轮廓或较薄的环带附近，寻找 `Coverage centroid` 记录，解释平均点为什么不一定与圆圈重合。实际采用的规则以记录中的标签为准。
3. 使用第 6 节的教学例子解释遮挡独立性。固定几何、逐个改变遮挡样本的情况由专项测试覆盖；旋转相机则会同时改变几何投影。
4. 用 Compare 对照 SSAA 与 MSAA，说明逐样本多次着色和一次共享着色的差别。每条记录的调用数看 Shading calls，整个视图的调用总数看 Frame cost 中的 Shades。
5. 如果被问到土星局部闪动，说明单次共享着色仍难以完整表现细密阴影；细密阴影过滤作为后续优化方向保留。

首次演示可以重点展示中心和平均点。固定后备用于特殊有效性处理，可结合已有受控测试说明。

## 9. 已验证的内容与范围

以下汇总开发阶段的实现与性能优化验证。当前公开测试入口可以直接运行；跨版本实验保留已有结果，连续播放观感验收和阴影过滤列为后续工作。

- 第三项及后续优化版的 Release 桌面构建、9 项测试通过；专项内存/数值检查覆盖光栅器、覆盖实现和相关测试，并通过检查。
- 专项测试包含 16 种深度遮挡组合、中心/平均点/后备、固定后备自身被挡住、透视属性、透明混合与记录回放。受控不透明异深度三角形交换提交顺序，旧规则有 1 个不同像素，新规则为 0；这项检查针对异深度不透明三角形。
- 第三项相对第二项完成版：32 张静态图中，24 张非 MSAA 图像完全一致，7 个发生变化的 MSAA 场景更接近同视角 SSAA16 参考，总览不变。SSAA16 提供更密采样的近似参考；局部变化另由逐像素记录分析。
- 土星微缩放的相邻误差变化指标约增加 0.15%，较大变化像素实例由 189 增至 218。这里统计的是相对参考图的误差在相邻帧间的变化，主观闪烁程度需要结合连续播放判断。
- 后续计算优化只减少重复计算：116 帧画面及核对状态、另外 168 次土星选点记录与第三项优化前一致，阴影和选点规则保持一致。
- 后续五轮计时中，7 个三角形 MSAA 场景均更快，中位耗时下降约 2%–9%；纯轨道耗时略增。普通采样的一次较大差异已独立复测并保留原数据。本组收益与第三项成本采用各自的比较基线，分别呈现。
- 已有 macOS / Metal 窗口检查确认规则文字、菱形、手动展开与重复点击保留状态。土星后续检查包含原尺寸关键帧与事件数据，连续播放的主观观感验收待补充。

后续可研究两项土星阴影过滤：一项处理环影落在球面上的细密明暗，另一项处理球体投向环带的硬边界。当前版本保留原有阴影规则。
