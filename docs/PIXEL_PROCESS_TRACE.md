# 像素过程检查

面向使用和演示的说明见 [第一项指南](第一项反馈-改动说明与查看指南.md)，包含栏目含义、教学例子和各级收起规则。构建与运行采用 [README](../README.md#桌面构建与验证) 的公开入口。

本文描述当前累计实现：三角形覆盖采用 top-left 与 16 位几何，MSAA 采用独立于深度结果的几何选点。详细规则见 [共享边说明](第二项反馈-共享边规则与验证.md)、[MSAA 说明](第三项反馈-实现与验证.md)。过程数据由渲染器直接采集。

## 怎么看

1. 打开桌面程序，选择行星并进入近景。
2. 开启 `Inspect` 或 `Compare`，点击画面中的像素。
3. 在右侧 `Pixel` 页展开 `Details → Processing history`。这个入口默认收起，像素放大图、最终样本结果及性能表继续保留。
4. 通过 `Record … of …` 选择一条真实处理记录。先看覆盖、深度通过、着色调用、颜色写入的摘要；圆点代表采样位置，菱形代表实际着色位置。绿色代表写入，橙色代表跳过，灰色代表未覆盖，表格同时给出文字原因。
5. 需要详细数值时，展开 `Shading and depth values`，查看每次着色的位置、线性 RGB、透明度、实际接收该颜色的样本，以及逐样本的深度前值/候选值/后值与混合前后颜色。`Final resolve` 展示全部最终样本平均后的线性颜色与显示 RGB。

比较视图只记录点击一侧的处理历史，左右放大图仍同步。切换像素、行星或采样方法时，`Details` 及其所有子项都回到收起状态，处理记录回到第一条。任意一级收起都会重置下面的全部子项，再次打开时需要逐层点击：`Details` 包括整个处理历史；`Processing history` 包括初始背景、着色与深度数值、最终合成及更深层的采样点详情；`Shading and depth values` 包括所有 `Sample … details`。同级分支保留原状态。同一选择的画面刷新和测速完成后，已展开的内容继续保持。

普通单采样在中心计算颜色，SSAA 记录各样本的实际调用。当前三角形 MSAA 在详情中显示 Pixel center、Coverage centroid 或 Covered sample fallback；后备时说明中心或平均点未采用的原因。菱形标记着色位置，可以位于采样圆点之间；圆点标记覆盖采样位置。独立大气 MSAA 保留 First eligible ray sample。没有实际着色时不画着色菱形；算出零 alpha 时仍记录真实调用。MSAA 为每个三角形片段在当前像素内共享一次着色；整个像素的调用数由参与的图元和效果累计而成。

## 记录的含义

- 初始背景与最终样本均来自真实样本缓冲区。覆盖、深度、着色、混合和写入均在实际发生时留下记录。
- 一个事件代表一个覆盖了至少一个采样点的三角形片段、轨道线段或大气处理。三角形保留裁剪前的源编号与裁剪片段编号；编号只在当前渲染内有效。完全未覆盖任何样本的图元不进入历史。
- 每条事件保存全部样本的前后状态，包括未覆盖和被拒绝的样本。`shading_index` 关联真实着色调用，多个样本可以引用同一次调用。着色次数与写入次数分别统计。
- 云层使用实际的层底色，可能与该次写入前的颜色不同；记录同时保留这两个值。星环保留透明度及混合来源。轨道使用固定颜色，着色调用数为零。大气记录射线可见区间、着色和颜色混合，深度测试标记为 NotTested，并保留原深度与物体归属。
- 每帧只跟踪选中的一个像素，最多保存 4096 条事件，超限时界面明确提示历史被截断；最终样本和最终图像仍完整。完整历史可以逐事件重建最终样本。

## 性能与验证

`RenderConfig::trace_process` 控制详细过程采集，必须同时有有效的选中像素坐标才会产生记录。为 `false` 时，最终样本查看仍可使用。`render_ms` 的渲染区间在开启过程采集时包含采集开销，因此桌面的同步与后台测速都显式关闭过程采集；3 次预热和 11 次正式样本结束后，用一次不计入统计的渲染恢复历史。移动像素选择保留已完成的耗时中位数。

自动测试包括：四种采样模式的记录开关前后图像/拾取/着色计数一致；从初始样本逐事件还原最终结果；部分覆盖和遮挡；MSAA 几何选点与共享关系；云层底色、透明星环、轨道、大气混合；近裁剪场景；比较视图坐标归属；记录上限；同步与异步测速关闭记录并在结束后恢复。当前 macOS Release 桌面构建和全部 9 项测试通过。原生 Metal 界面检查覆盖默认折叠、展开、切换采样方法、测速恢复和最小窗口宽度。Windows/Linux GUI 待进行原生环境验证。


## 直接运行的验证入口

先完成 README 的桌面构建，再从项目根目录运行：

```sh
ctest --test-dir build -C Release -R '^planet_pixel_trace_tests$' --output-on-failure
```

专项命令运行像素记录测试；包括 UI 在内的完整回归使用 README 中的 CTest 命令。两种入口均使用项目自带测试。
