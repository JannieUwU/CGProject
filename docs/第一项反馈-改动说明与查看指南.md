# 第一项反馈：改动说明与查看指南

更新时间：2026-11-21。

本文说明当前版本的像素过程记录、查看方法和逐层展开规则。当前已包含共享边修复与 MSAA 几何选点；后两项分别见 [第二项指南](第二项反馈-改动说明与查看指南.md)、[第三项指南](第三项反馈-改动说明与查看指南.md)。

## 1. 这次做了什么

原来能看到采样点的最终结果，但不容易回答“哪些表面参与过处理、为什么被挡住、颜色在哪里计算、写给了哪些点”。现在可以在右侧 `Pixel → Details → Processing history` 中查看当前帧、当前选中像素的真实处理记录。

| 改动 | 现在能看到什么 | 带来的好处 |
| --- | --- | --- |
| 补充处理记录 | 图元及物体、几何覆盖、深度测试、跳过原因、实际着色位置和结果、接收颜色的采样点 | 把最终颜色与实际计算步骤对应起来 |
| 统一三种主要方法 | 普通单采样、4× SSAA、4× MSAA，兼容已有 16× SSAA | 可以用同一套信息比较各方法计算了什么、共享了什么 |
| 记录特殊效果 | 云层、星环、轨道、大气的真实处理与混合；哪些步骤没有执行深度测试或着色也会如实区分 | 分别解释各类效果的处理方式 |
| 增加渐进展开的入口 | 保留像素放大图、性能表和最终 Samples，在 Details 中增加 Processing history | 平时先看效果，需要解释时再逐层打开 |
| 统一所有层级的收起规则 | 收起父项会重置全部后代；换像素、换星球或采样方法时全部收起 | 再次查看不会一下展开一大串旧详情 |
| 分开过程记录与正式测速 | 正式测速暂停详细记录，结束后自动恢复 | 减少详细记录对性能比较的干扰 |

第一项负责让真实计算过程可见；当前程序同时采用第二项的 top-left 共享边规则，以及第三项的 MSAA 几何选点。下面的例子和操作均按当前行为说明。

## 2. 适用版本与运行入口

适用于包含三项反馈、重复点击修复、16 位精度打磨和后续计算优化的当前源码。先按 [README 的桌面构建与验证](../README.md#桌面构建与验证) 完成构建，然后使用其中的桌面启动命令。

所有说明统一从项目根目录操作、使用 `build` 作为桌面构建目录；不需要开发者本机的旧分支、预览应用包或实验目录。已有项目可由程序中的 Load 打开。

## 3. 如何进入并查看

1. 打开程序，选择地球或土星，等待镜头进入近景。
2. 开启顶部 `Inspect`，点击画面中想检查的像素。也可以开启 `Compare`，在同一场景下比较左右两种采样方法。
3. 选中像素后，右侧会切到 `Pixel`。先看 `Pixel zoom` 的放大结果。
4. 手动展开 `Details`，查看位置、最终 RGB 和最终 Samples。
5. 再手动展开 `Processing history`，查看记录总数和实际着色调用总数。
6. 使用 `Record … of …` 选择某一条处理记录，先看覆盖、深度通过、着色和写入数量，以及采样点示意图。
7. 有疑问时再展开 `Initial background`、`Shading and depth values`、具体的 `Sample … details` 或 `Final resolve`。

`Region` 中的 `9 × 9`、`17 × 17`、`25 × 25` 是放大区域包含的原始像素数量；像素内的采样数量由采样方法决定。白框标记选中像素。选中画面后可用方向键微调位置。

比较视图会同步显示左右同一局部坐标的放大结果；详细处理记录和 Samples 来自实际点击的一侧。界面中的 `Samples: left/right view (clicked side)` 用来说明这一点。

## 4. 为什么点击像素后进入 Pixel

| 页签 | 主要用途 |
| --- | --- |
| Design | 修改行星外观和地形 |
| Orbit / Physics | 查看或编辑运动、轨道和物理参数 |
| Pixel | 解释画面中的一个像素如何产生，比较抗锯齿方法 |

开启 Inspect 后，点击动作表达的是“检查这个像素”，因此自动切到 Pixel 可以直接显示结果。正常编辑星球外观时则使用 Design。进入 Pixel 后，Details 保持收起，点击即可查看详细内容。

这是当前交互行为的说明；自动选择 Pixel 的基础行为沿用原有实现。

## 5. 每一项是什么意思

界面结构如下，Samples 与 Processing history 同属 Details；Final resolve 汇总整个像素处理结束后的最终合成。

```text
Pixel
├─ Pixel zoom                         像素及邻域放大图
├─ Frame cost                         整个视图的渲染开销
└─ Details                            选中像素的详细资料
   ├─ Pixel / RGB / Filter            坐标、最终颜色、放大过滤方式
   ├─ Processing history             当前帧内，这个像素的处理过程
   │  ├─ Initial background          处理前各采样点的背景颜色
   │  ├─ Record … of …               选择当前查看的处理记录
   │  ├─ 摘要、示意图和状态表          本条记录的覆盖、遮挡、着色、写入
   │  ├─ Shading and depth values    本条记录的着色与深度数值
   │  │  └─ Sample … details         本条记录对某一个采样点造成的变化
   │  └─ Final resolve               全部处理结束后的颜色合成
   └─ Samples                        全部处理结束后，各采样点的最终结果
```

| 名称 | 用人话理解 |
| --- | --- |
| Pixel zoom | “这个位置放大以后长什么样？”用于看轮廓、锯齿和颜色过渡。 |
| Frame cost | “整幅视图算了多少次颜色、花了多久？”Method 是采样方法；Shades 是整个视图的着色次数；Time 是稳定画面的 CPU 渲染耗时中位数。统计范围是整个视图。 |
| Details | “打开这个像素的资料夹。”包含坐标、最终颜色、过程记录和最终样本。 |
| Processing history | “这个像素在当前帧里经历了什么？”记录当前这一帧的完整处理顺序。 |
| Initial background | “任何物体画上去之前，这些采样点是什么颜色？”初始深度 infinity 表示还没有物体写入深度。背景也可能包含星空。 |
| Record … of … | “现在看第几次处理？”一条记录可能来自一个三角形片段、轨道线段或大气处理。图元编号是标识，Record 序号才是这里的记录顺序。 |
| Covered | “这块几何有没有盖住这个采样位置？”覆盖后还需通过遮挡等检查，才能写入。 |
| Passed depth / Depth test | “它有没有被已经记录的、更近的表面挡住？”当前实现中较小的深度更近。有些效果不执行传统深度测试，会如实显示。 |
| Shading calls | “实际计算了几次颜色？”可以不同于覆盖数或写入数，MSAA 可能让多个点共用一次结果。 |
| Color writes / Outcome | “哪些采样点真的更新了颜色？没更新的原因是什么？”例如未覆盖、被遮挡、无透明度或云层背向镜头。 |
| Shading and depth values | “在哪个位置算出的颜色、算出了多少、实际写给了哪些点？”位置使用像素内部的局部坐标；这里的 RGB 是计算用的线性颜色。 |
| Sample … details | “这一步处理前后，这一个采样点的深度和颜色怎样变化？”Before 是原值；Candidate 是候选深度；After 是保留下来的结果。 |
| Source RGB / Alpha / Blend base | “新颜色是什么、它有多不透明、与哪份底色混合？”云层可以使用保存的层底色进行混合。 |
| Final resolve | “把所有最终采样点怎样合成屏幕上的一个像素？”先平均线性颜色，再进行显示转换。 |
| Samples | “所有处理结束后，各个点最后留下了什么？”对应全部处理完成后的样本状态。 |

处理示意图中的圆圈表示采样位置，菱形表示实际着色位置。绿色表示写入，橙色表示覆盖后跳过，灰色表示未覆盖；这些颜色表达处理状态；Details 下的最终 Samples 显示样本实际留下的颜色。

没有几何或效果覆盖采样点时，可能没有处理记录，界面会说明背景保持不变，部分几何详情不会出现。

## 6. 用一个例子串起来

下面用一个简化的教学示例说明处理步骤。假设你点击了地球轮廓处的一个像素，使用 4× MSAA；背景简化为黑色，表面着色结果简化为蓝色，暂不考虑云层和大气。

一个像素内有 4 个采样位置，相当于在一个小格子里放置了 4 个检查点，最后合成为一个屏幕像素。

### 第一步：看 Initial background

4 个点都从黑色开始，深度均为 infinity。此时还没有表面占据这些位置。

### 第二步：看第一条处理记录

一块地球表面三角形覆盖了采样点 1、2、3，深度均为 2。它们之前没有表面，因此都通过深度测试。

摘要会对应：覆盖 3 个点，深度通过 3 个点，实际着色 1 次，写入 3 个点。本例假定像素中心属于当前三角形且属性有效，MSAA 在中心 `(0.5,0.5)` 计算出蓝色，再把结果共享给这 3 个点。第 4 个点未被覆盖，继续保留背景。

### 第三步：展开 Sample 1 details

| 字段 | 教学示例中的值 | 含义 |
| --- | --- | --- |
| Before depth | infinity | 原来没有物体 |
| Candidate depth | 2 | 新表面位于深度 2 |
| Depth test | passed | 可以写入 |
| After depth | 2 | 现在记录这块表面 |
| Before RGB | 黑色 | 原来是背景 |
| Source / After RGB | 蓝色 | 本次不透明表面直接写入蓝色 |

### 第四步：切换到第二条处理记录

另一块更远的表面覆盖了点 1、2，候选深度为 5，而这两个点已经记录深度 2。因为 5 更远，这次被挡住，不写入颜色，也不需要为这些全部被挡住的样本计算颜色。

此时 Sample 1 details 会解释：处理前深度是 2，候选深度是 5，测试被拒绝，处理后仍为 2，颜色仍是蓝色。

处理记录同时保存成功写入和跳过的情况，以及对应原因。

### 第五步：看最终 Samples 与 Final resolve

最终 4 个点分别为“蓝、蓝、蓝、黑”。Final resolve 将它们的线性颜色平均，再转换成显示颜色。结果包含 3 份地球颜色和 1 份背景颜色，表达地球只覆盖了这个像素的一部分，让轮廓过渡更柔和。

如果把示例中的蓝色写成线性 RGB `(0, 0, 1)`，黑色写成 `(0, 0, 0)`，平均值为 `(0, 0, 0.75)`。界面上的最终 0–255 RGB 还经过显示转换，不应直接把 0.75 乘以 255 当作最终显示值。

对这个同样的三点覆盖示例，4× SSAA 会分别在 3 个合格采样位置计算颜色；4× MSAA 共享一次计算。一次共享着色对应一个三角形片段在该像素内的处理；真实像素还会累计其他三角形和效果的调用。

## 7. 展开与收起的统一规则

| 操作 | 预期表现 |
| --- | --- |
| 开启检查，选中一个像素 | 自动切到 Pixel；Details 及其子项默认收起 |
| 展开 Details | Processing history 仍需单独点击 |
| 收起 Details，再打开 | 所有内部层级均恢复收起 |
| 收起 Processing history，再打开 | Initial background、Shading and depth values、Final resolve 及更深的 Sample details 均恢复收起 |
| 收起 Shading and depth values，再打开 | 所有 Sample details 恢复收起；同级 Initial background、Final resolve 不受影响 |
| 换像素、换星球或切换采样方法 | Details 及全部后代收起；处理记录回到第一条 |
| 同一选择的正常画面刷新、测速完成 | 不打断正在展开查看的内容 |
| 再次点击当前近景星球的名称 | 保留镜头、像素选择、检查模式、详情和有效测速 |

## 8. 建议怎样演示

首次演示按“看效果 → 看数量 → 看原因 → 看合成”的顺序进行，遇到具体问题时再展开数值。

1. **地球轮廓**：用 Compare 对比 1x 与 4× MSAA，点轮廓附近。先看放大图，再找到一条部分覆盖的表面记录，解释覆盖数量与着色次数的区别。覆盖数量以选中记录为准。
2. **具体遮挡**：选择一条显示 `Blocked by depth` 的记录，展开对应 Sample details，解释候选表面为什么没有替换原结果。
3. **土星环或云层**：检查带透明度的处理记录，查看 Source RGB、alpha、实际混合底色与 After RGB，说明“混合”与不透明“替换”的区别。
4. **收起验证**：打开到 Sample details，依次关闭它的不同上级，再重新展开，确认下级保持收起；再选其他像素或星球，确认全部重置。

## 9. 已验证的内容与范围

- 当前累计版本的 macOS / Metal Release 桌面构建及 9 项测试通过。测试入口见 README；专项检查可使用下面的 CTest 命令。
- 记录开关前后的图像、物体拾取和着色计数一致；过程记录可以重建最终样本，并覆盖云层、星环、轨道、大气及近裁剪场景。
- 自动界面事件测试覆盖父项关闭后所有后代重置、换像素和星球重置、同级分支不受影响，以及 1、4、16 个采样点的详情状态。
- 正式测速关闭详细过程记录，测速结束后自动恢复；移动像素选择保留有效的性能统计。
- 每帧只为选中的一个像素记录，最多 4096 条事件；超过上限会提示截断，最终样本仍完整。
- 本次验证平台为 macOS / Metal；Windows / Linux 原生 GUI 待验证。

```sh
ctest --test-dir build -C Release -R '^planet_pixel_trace_tests$' --output-on-failure
```
