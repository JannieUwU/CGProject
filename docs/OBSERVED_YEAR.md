# 2025 年 11 月 28 日至 2026 年 11 月 28 日轨道预设

该预设从 NASA/JPL Horizons 的三维初始状态出发，用已有 REBOUND IAS15 积分器推进 365 天。它用于展示椭圆轨道、轨道倾角与三维镜头跟随，是九天体牛顿引力近似，不是完整的 JPL 星历重现。

## 使用

在 Design 模式点击 `Run simulation`，选择 `2026 Real Trajectory` 或 `Theoretical Simulation`。进入 Simulation 后，顶部 `Simulation mode` 下拉框也可切换。

从理论模式切换到 `2026 Real Trajectory` 时使用标准 Horizons 初始条件及这一年范围，不沿用理论模拟中修改过的质量、位置和速度。已加载或正在编辑的年度项目选择该模式运行时，保留当前质量、位置、速度和外观设计；返回 Design 后再次运行也保留这些修改。它仍是近似数值模拟，界面会标明日期范围与近似性质。`Theoretical Simulation` 使用原教学轨道和 DIY 物理参数。

切换重置模拟时间、跟随与分析状态，保留外观设计，并在本次会话中缓存切换前的理论模拟项目，切回时恢复其物理初始条件。从年度 JSON 直接启动、没有本次会话理论缓存时，理论模式使用原来的教学默认参数。该缓存不会写入项目文件，加载其他项目时清除；Save 保存当前模式的项目。

选择真实轨迹模式后，Simulation 信息面板显示日期。默认 1x 表示现实一秒推进一个模拟日，Speed 可调整；Step 推进 0.025 天。拖动 Time 在 0–365 天之间定位，抵达终点自动暂停。日期范围为 2025-11-28 00:00 TDB 至 2026-11-28 00:00 TDB，TDB 是天文动力学时间，不是北京时间；界面没有把它转换为 UTC 或当地时间。

点击行星或 `Follow selected` 后，镜头跟随行星的三维位置，右键旋转、滚轮缩放。`Full system` / `Inner system`和 `Back to system` 可恢复全景。跟随不会把相机自动旋转到速度方向，保留用户选定的观察角度。Compare 暂停时间推进并复用同一三维状态。

也可通过 Load 打开 `examples/observed-year.json`，或从项目根目录运行：

```powershell
.\build\Release\planet_studio.exe examples/observed-year.json
```

旧项目的 `[x,y]` 位置、速度继续可读，缺失的 z 默认为 0；新保存的状态包含 `[x,y,z]`。`epoch_jd`、`duration_days`、`gravitational_constant` 随项目保存。年度项目的时长必须大于 0 且不超过 365 个 TDB 日，超范围文件在加载时报告错误；理论模式仍支持原有的模拟时长。修改质量、位置或速度后是基于该时间窗口的 DIY 变体，不再对应原始天文轨迹。

## 数据和单位

- 来源：[Horizons API](https://ssd-api.jpl.nasa.gov/doc/horizons.html)，原始响应在 `assets/ephemeris-year/horizons-*.txt`；`states.json` 保存完整查询 URL、日期、初始状态与验证状态。
- 初始历元 JD 2461007.5 TDB，终点 JD 2461372.5 TDB。
- 原点为太阳系质心，参考系为 J2000 黄道面，采用几何状态向量，不含光行时或视位置修正。坐标映射为 x、y、z 原样传入场景，z 为离开黄道面的方向。
- 目标编号为太阳 10 与行星系统质心 1–8。地球代表地月质心，其他带卫星行星代表其系统质心，渲染仍使用单个行星模型，未单独模拟卫星。
- 长度 AU，时间日，质量为太阳质量；引力常数由太阳 GM 换算。质量使用 [JPL DE440 GM 表](https://ssd.jpl.nasa.gov/astro_par.html) 的系统 GM 与太阳 GM 之比，地月项合计地球和月球 GM。Horizons 返回轨道源为 DE441。
- 碰撞半径使用名义物理半径换算为 AU，仅影响接触与合并；渲染半径仍为独立的教学放大值，不按真实大小显示。半径近似值随刷新脚本列出，可参考 [JPL 行星物理参数](https://ssd.jpl.nasa.gov/planets/phys_par.html)。显示球体仍可能提前视觉相交，实际碰撞按物理半径判断。

所有初始状态已编译进程序，无需运行时联网或安装 Python。维护者可用标准库脚本 `python tools/fetch_observed_year.py` 重新请求数据；`--offline` 从保留的原始响应重新生成 C++ 数据与示例 JSON，不访问网络。刷新数据后应重新构建和运行测试。

## 验证与限制

`planet_observed_year_tests` 比较起点、2026-02-28、05-28、08-28 与终点的九天体位置。首次 Windows Release 验证中最大抽查差约 448.236 km，出现在终点的水星；测试为各抽查点设置 1000 km 回归上限。这不是对整个区间所有时刻的误差保证，也不适用于用户修改初始条件后的项目。

模型不包含相对论、太阳非球形引力、小行星与独立卫星摄动等完整星历效应。自转和材质仍沿用现有展示模型，不能把轨道数据来源理解为真实自转姿态、表面纹理时相或真实天气。

测试还覆盖三维项目保存读取、旧二维格式、第三维碰撞距离、回退重放、年末停止、三维近景居中、深度平移一致性与 Compare 冻结。三维位置同时用于球体、环带、轨迹、太阳光方向、拾取画面有效性、碰撞接触和特效；UV 和像素采样坐标保持二维。

本次在 Windows 上完成 Release 构建，桌面配置 11/11 测试通过；使用独立示例项目实际打开窗口，检查了日期、三维状态显示和水星近景持续跟随。

轨迹保留的是已经模拟的历史，不是未来预测；本预设约每半天记录一次，最多 1024 点，足以覆盖一年。外行星在一年内只能走过轨道的一部分，界面不会将这一段伪装成完整公转轨道。Mac 需要重新构建和验收，本次 Windows 验证不能代替 macOS 验证。
